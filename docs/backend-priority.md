# ShiftRhythm Backend 구현 우선순위

## 기술 기준

- Java 21, Spring Boot 4.1, Gradle
- MySQL: 영구 데이터의 원본 저장소
- Redis: Refresh Token 저장 및 로그아웃 무효화, 향후 캐시·요청 제한 확장
- Flyway: DB 스키마 버전 관리
- Spring Security: Google ID Token 검증 후 자체 JWT Access/Refresh Token 발급
- 환경변수: DB, Redis, JWT 비밀키, Google Client ID 같은 비밀값을 소스에서 분리

## 공통 API 규칙

- Base URL은 `/api/v1`이다.
- 오류 응답은 `{ "message": "..." }` 형식을 사용한다.
- 요청 검증 오류는 400, 인증 실패는 401, 소유권 위반은 403, 리소스 부재는 404, 상태 충돌은 409로 통일한다.
- 날짜는 `yyyy-MM-dd`, 시간은 ISO-8601 offset datetime을 기본으로 한다.
- 사용자별 리소스의 소유권 검사는 서비스 계층에서 수행한다.

## 구현 순서

### P0 — 플랫폼 기반

Docker Compose, 환경변수 계약, MySQL·Redis 연결, Flyway, 공통 예외 처리, 보안 필터 체인을 구성한다.

**상태: 완료**

### P1 — 인증 및 사용자

Google 로그인, 자체 JWT 재발급·로그아웃, 내 정보, 사용자 설정 및 알림 설정을 구현한다. 모든 개인화 API의 사용자 식별과 설정값을 제공한다.

### P2 — 근무 일정

수동 일정 CRUD, 기간 조회, 4주 충족도, 일괄 변경, 반복 패턴을 구현한다. OCR 없이도 사용자가 일정 데이터를 완성할 수 있어야 한다.

### P3 — 코칭, 전환 프로토콜, 홈

일정과 사용자 설정에서 코칭 카드·전환 프로토콜·홈 대시보드를 생성한다. 일정 변경 시 영향 범위의 코칭을 재계산한다.

### P4 — 루틴 및 낮잠 타이머

코칭·전환 결과로 생성한 루틴을 완료 또는 건너뛰기 처리하고, 스트릭·리포트를 계산한다. 낮잠은 사용자 설정의 횟수·권장 시간을 적용하고 동시에 하나만 실행하도록 제한한다.

**상태: 완료** (루틴은 코칭 생성·재생성 시 코칭 카드와 전환 프로토콜 당일 단계에서 자동 생성된다. `local` 프로파일의 고정 사용자(`id=1`)는 개발 편의용으로 유지한다.)

### P5 — OCR 일정 입력

이미지 업로드, 비동기 OCR 작업 상태 조회, 초안 검수·보정·확정, 재시도를 구현한다. OCR 결과는 검수 후에만 실제 일정에 반영한다.

**상태: 완료** (Document AI Form Parser + 서비스 계정 impersonation, `docs/superpowers/specs/2026-08-18-ocr-schedule-input-design.md` 참조)

### P6 — AI 채팅 및 영양 콘텐츠

채팅은 의료·응급 안전 분기, 계산 완료 컨텍스트 주입, OpenAI Structured Outputs, 피드백·이력을 구현한다. 영양 콘텐츠와 즐겨찾기 외에 사용자가 직접 등록하거나 건강검진에서 확인한 영양소 목표를 제품 기능성 원료와 규칙 기반으로 매칭한다. LLM은 결핍을 진단하거나 제품 후보를 선택하지 않고 백엔드가 만든 후보와 표시 기능정보를 설명만 한다.

**상태: 완료** (채팅·수면·카페인 컨텍스트, 영양 콘텐츠·즐겨찾기, 사용자 등록 영양소 목표 기반 VIVEGEN 제품 규칙 추천 구현)

## 테스트 원칙

- 새 동작은 테스트를 먼저 작성하고 실패를 확인한 뒤 최소 구현을 추가한다.
- 서비스 계층은 단위 테스트로, HTTP 계약과 보안 흐름은 통합 테스트로 검증한다.
- MySQL·Redis 상호작용이 필요한 통합 테스트는 실제 컨테이너 기반으로 검증한다.
